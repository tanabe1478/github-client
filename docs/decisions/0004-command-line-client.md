# ADR 0004: CLIの`ghclient`は単体で動かし、アプリとはデータファイルを共有する

- Status: Accepted
- Date: 2026-09-29

## Context

利用者から「このアプリの操作をCLIからも出来るようにしたい。AIを使った自動化もやりやすくなる」という要望があった（2026-09-29）。

アプリにはcontrol fileがあるが、これは起動中のアプリの画面を動かして撮るための仕組みで、結果を受け取れない（ADR 0001の改訂を参照）。

## Decision

- `ghclient`は、アプリを起動していなくても使える別のコマンドにする。GitHub APIとアプリの保存データを直接使い、結果をJSONで返す。
- 取得と項目への変換は`modules/activity_sync`に移し、アプリとCLIで共有する。
- アプリは保存ファイル（Doneの記録、SaveとUnsubscribeの記録、Watch一覧、設定）を2秒ごとに確認し、外部で変更されたものを読み直す。新しくWatchされたリポジトリはbackgroundで取得する。
- コマンド、JSONの形、終了コードは`docs/cli.md`に書く。

設定ファイル`settings.txt`を、人やAIが直接編集できるコメント付きの`key = value`形式にしたのも同じ方針である。利用者は「AIにも変更させるようにするから」と説明している（2026-10-06）。

## 検討した案

- 起動中のアプリを操作するCLI: local socketでアプリとやり取りする。アプリの起動が前提になり、アプリ側に通信serverの実装が要る。利用者が単体で動く案を選んだ。

## Consequences

### Positive

- アプリを起動しなくても、scriptやAI agentから一覧の取得とトリアージができる。
- アプリとCLIで取得と変換のコードが1つになる。

### Negative

- アプリとCLIが2秒以内に同じファイルを変更すると、後から書いた側の内容が残る。
- アプリへの反映は最大で約2秒遅れる。2秒という間隔を選んだ根拠は記録がない。
- CLIは呼び出すたびにGitHubから取得する。
